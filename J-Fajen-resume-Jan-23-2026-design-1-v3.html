The "Uncle's Garage" Transformation -- Marlowe Documentation, IOHK

Challenge

Cardano's Marlowe smart contract platform had documentation scattered across multiple repositories -- like walking into an uncle's garage where valuable tools are buried under years of accumulated chaos. Developers couldn't find what they needed; potential users couldn't get started.

Action

I took sole ownership of the documentation transformation. Over 13 months, I authored 17,900+ lines of code across 124 files, accounting for 78% of all repository commits. I designed an information architecture with 5 distinct user personas and visual pathway diagrams, created a 91-schema OpenAPI specification documenting the 7-service runtime architecture, and established weekly engineering syncs that resulted in 59 merged PRs.

Result

A unified, authoritative documentation site that transformed fragmented chaos into a clear, navigable resource. Built with a pre-adoption strategy -- comprehensive docs ready for users who don't exist yet, enabling growth from day one.

When Documentation Needed AI -- Essential Cardano Assistant

Challenge

The Cardano ecosystem spans thousands of documents across dozens of sources. Users needed instant, accurate answers -- but any AI assistant in this space risked hallucination, which in blockchain could mean real financial consequences.

Action

I built a production AI chatbot end-to-end, solo. I ingested 2,500 documents from 8 sources, built a complete extraction pipeline, and iterated through 20+ system prompt versions until achieving zero detectable hallucination and 100% fact accuracy across targeted test queries. I deployed a professional Next.js web UI with streaming and conversation persistence, established Railway production infrastructure, and resolved critical blockers independently -- 91 commits from concept to production.

Result

A production-ready AI assistant that provides accurate, trustworthy answers to complex blockchain questions.

I created a multi-LLM comparison framework testing OpenAI, Anthropic, and Gemini APIs to find the best approach for each documentation challenge.

Result

25+ FAQ entries derived from Discord analysis, plus a reusable methodology for community-sourced documentation. When documentation challenges arise, I don't just write -- I build systematic solutions.
